# Dock window animation

`HideAnimation=liquid` adds the **iOS 水滴** choice in KOS Settings → 窗口和动画 → 隐藏与恢复. Existing `none`, `scale` and `genie` choices retain their behavior. Closing a window remains independently configured. Standard `kosctl install` installs this plugin and chooses liquid for new configurations; existing explicit and legacy animation selections are preserved.

Liquid defaults to 240ms minimize and 160ms restore, independently configurable through `LiquidMinimizeDuration` and `LiquidRestoreDuration` in the effect group. The liquid transition moves and shrinks the window with one continuous easing toward its Dock target, with modest symmetric corners capped at 24% of its short side. Window content remains visible until the final 80ms of canonical minimize time: it then crossfades into cached Dock artwork over 25ms, holds the full icon for 35ms, followed by a 20ms fade into the permanent Dock icon. The icon inherits the same geometry, without a size jump. Restore traverses the same poses backwards (the timing scales with restore duration), and reversal reuses the cached texture. Icon corners are baked into the cached image; icon rendering uses KWin's standard texture shader.

Artwork comes from the existing target payload's `iconSource`, using local file URLs, absolute paths or themed `image://icon/` names; otherwise it uses `EffectWindow::icon()`. It is rasterized once per animation and uploaded once on the first draw. Missing artwork or a failed texture upload falls back to the existing window scale path. There is no background sampling, blur capture or real-time refraction for the icon. Frame-time improvement has not been measured; ordinary composition and background rendering still cost time.

## Guest demo

For an OpenGL guest that KWin considers too slow for animations, `AllowSoftwareDemo=true` in `[Effect-kos_dock_window_animation]` explicitly permits this effect alone. It defaults to false and does not override KWin's protection for other plugins. The llvmpipe guest is suitable for inspecting the transition, not for judging hardware GPU performance. Disable this setting after the demo if software animations are no longer wanted.

Replace plugins atomically and start a fresh guest login; do not unload/reload a replaced KWin shared library in the running session. Select iOS 水滴, then minimize/restore a window represented in the Dock. Test rapid reversal, SSD and CSD windows, missing artwork, different output scales and a hidden/moved Dock. `/KOSDockWindowAnimation`'s `status()` reports `iconUploads`, `iconOnlyDraws` and `liquidWindowDraws` to distinguish the icon tail from window drawing. These are draw-call counters, not frame-time measurements.

`kos-dock-animation.liquid-motion` verifies finite geometry, crossfade endpoints, icon-only tail, phase continuity and repaint bounds, including negative monitor coordinates. Settings tests verify the new choice and persistence. `tests/run-live.sh` runs an isolated local KWin session using the built plugins, captures minimize/restore frames, and asserts icon drawing, upload caching, rapid reversal and source destruction mid-flight. It covers shared-source SSD, frameless CSD at 150% scale, the legacy offscreen path with KOS appearance disabled, and a real Quickshell Dock backed by a private platform daemon. It uses slowed timelines for contour inspection; this is not a frame-time benchmark. `KOS_LIVE_DURATION=300 KOS_LIVE_SCENARIOS=real-dock tests/run-live.sh` repeats the real Dock case at normal speed. `KOS_LIVE_SCENARIOS=real-dock-glass tests/run-live.sh` additionally enables the installed Glass plugin to inspect the Dock handoff with liquid material active. Each case retains logs and screenshots under `.build/kosctl/liquid-live/`. The runner never replaces the current desktop compositor. Screenshot permission bypass is scoped to the isolated test compositor.

The shape and timing follow the requested iOS-like behavior; exact frame matching still requires a reference recording. Install both Bridge and Dock plugins together, then log in again to load them. Do not overwrite loaded shared-library inodes or hot-reload replaced plugins.

For compositor cadence diagnostics, run `KOS_LIVE_NO_CAPTURE=1 KOS_LIVE_DURATION=300 KOS_LIVE_SCENARIOS=real-dock-glass tests/run-live.sh`. This disables screenshot work during the transitions. Status fields `paintIntervalSamples`, `paintIntervalMedianMs`, `paintIntervalP95Ms` and `paintIntervalMaxMs` report a bounded history of consecutive same-view CPU prepaint callbacks. They are cadence diagnostics, not GPU render durations or confirmed display presentation times. Multi-view histories may have fewer samples. Compare actual desktop recordings/measurements separately before claiming a performance improvement. The fallback source is retained through icon-only frames for reversal and destroyed on animation completion; no extra context switch occurs in the ordinary draw callback.

New-app opening uses a separate 180ms window expansion with cubic ease-out and a prompt content fade-in. It does not reuse liquid icon crossfading or prepare icon textures; `OpenDuration` can override its duration.

Dock targets use the rendered artwork rectangle, including hover magnification and lift. Geometry updates are throttled rather than delayed until pointer animation settles. Minimize no longer destroys/recreates the Dock icon renderer near handoff; renderer recreation remains reserved for icon-theme changes. Motion checks include monotonic distance to the Dock to catch geometric overshoot.
